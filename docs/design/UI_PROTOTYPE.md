# Codex Provider Hub：桌面工具 UI 原型稿

> 状态：设计基线（已接入 Vue 实现）  
> 目标：把 Codex Provider Hub 组织成一个长期驻留、可快速切换配置的 Windows 工具，而不是一张铺满表单的网页。

可视化原型：[`ui-prototype.svg`](ui-prototype.svg)

## 1. 设计定位

**设计判断**：这是一个给开发者高频使用的配置切换工具，主要任务是确认当前 Codex 使用哪一个 Provider / Model / Profile，然后快速切换或修复配置。

界面应接近桌面工具的工作台：固定导航、紧凑信息密度、明确的当前状态、短路径操作。参考 CC Switch 的“工具壳 + 列表 + 弹窗”组织方式，但不复制其品牌或页面细节。

### 明确不采用的网页模式

- 不使用首页 Hero、营销式大标题或长段介绍。
- 不把 Provider、Model、Route、Profile、Windows 设置同时铺成五个大卡片。
- 不让用户通过滚动整页寻找主要操作。
- 不把编辑表单常驻在列表下面；创建和编辑使用弹窗。
- 不用阴影、渐变和大圆角制造“网页卡片感”。

### 桌面窗口基准

| 项目 | 基准 |
| --- | --- |
| 最小窗口 | 960 × 640 |
| 推荐窗口 | 1120 × 760 |
| 左侧导航 | 216 px，固定，不随内容滚动 |
| 顶部工具栏 | 52 px，固定 |
| 内容区内边距 | 24 px（窄窗口 16 px） |
| 主列表行高 | 64 px |
| 控件最小高度 | 32 px；图标按钮点击区不小于 36 px |
| 内容滚动 | 只有主内容区滚动，导航和工具栏保持稳定 |

## 2. 应用壳层原型

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│  ● Codex Provider Hub                           当前档案 ▾   ↻   ● Codex 运行中 │  ← 顶部工具栏
├──────────────────┬───────────────────────────────────────────────────────────┤
│  CP  Codex Hub   │  配置                                                       │
│  本地 Provider 管理│  当前使用                                                     │
│                  │  ┌─────────────────────────────────────────────────────┐  │
│  WORKSPACE       │  │ ● CPA                                            已激活 │  │
│  ◉ 配置          │  │   gpt-5.6-sol · Responses API                 [重启] │  │
│    档案          │  │   Profile: 工作                                     │  │
│                  │  └─────────────────────────────────────────────────────┘  │
│  SYSTEM          │                                                               │
│  ⚙ 设置          │  Provider                                      [+ 添加]    │
│                  │  ┌─────────────────────────────────────────────────────┐  │
│                  │  │ ◉ CPA       cpa.example.com/v1       3 个模型       │  │
│                  │  │             当前使用 · Responses API       [切换] ⋯ │  │
│                  │  ├─────────────────────────────────────────────────────┤  │
│                  │  │ ○ OpenAI    api.openai.com/v1         2 个模型       │  │
│                  │  │             未激活                         [切换] ⋯ │  │
│                  │  └─────────────────────────────────────────────────────┘  │
│                  │                                                               │
│  ● 本地配置已同步 │  最近操作：已激活 CPA / gpt-5.6-sol                          │
└──────────────────┴───────────────────────────────────────────────────────────┘
```

### 壳层职责

- **导航栏**只负责切换一级页面：`配置`、`档案`、`设置`。
- **顶部工具栏**显示当前 Profile、Codex 运行状态、刷新入口；不放长说明。
- **主内容区**只呈现当前页面的核心任务。
- **底部状态**只显示同步、错误、备份等短状态，不能变成第二个信息面板。
- Wails 可以继续使用系统标题栏；如果后续需要无边框窗口，再单独增加自绘标题栏，不把网页标题栏伪装成产品内容。

## 3. 页面原型

### 3.1 配置页（默认页）

配置页是使用频率最高的页面，目标是“看一眼知道当前路由，点一次完成切换”。

#### 内容层级

1. 页面标题：`配置`
2. 当前路由摘要：当前 Provider、Model、Profile、Codex 运行状态
3. Provider 列表：按当前激活、最近使用、其他排序
4. 每个 Provider 的模型摘要：只展示启用模型数量和当前模型
5. 辅助动作：添加 Provider、刷新、打开编辑

#### 当前路由摘要

- 左侧使用状态圆点和 Provider 首字母图标。
- 主行显示 Provider 名称和 `已激活` 状态。
- 次行显示 Model、协议和 Profile。
- 右侧只保留一个主动作：`重新启动 Codex` 或 `启动 Codex`。
- 路由激活成功后，摘要区域更新并给出短暂的成功提示；不弹出阻塞式成功对话框。

#### Provider 列表行

| 区域 | 内容 |
| --- | --- |
| 左 | 图标、名称、Provider ID |
| 中 | Base URL、协议、启用模型数量 |
| 右 | `切换`、`编辑`、更多菜单 |
| 激活态 | 背景轻微提亮、状态点、`当前使用` 标签 |
| 空态 | `还没有 Provider` + `添加第一个 Provider` |

点击列表行打开 Provider 详情抽屉或弹窗；点击 `切换` 直接进入激活流程，不打开编辑表单。

### 3.2 Provider 编辑弹窗

```text
                 ┌─────────────────────────────────────┐
                 │ 编辑 Provider                    ×  │
                 │                                     │
                 │ 显示名称                            │
                 │ [ CPA                              ] │
                 │ Provider ID                          │
                 │ [ cpa                              ] │
                 │ Responses API 地址                   │
                 │ [ https://api.example.com/v1       ] │
                 │ 凭据引用                             │
                 │ [ 环境变量名或 credential:target   ] │
                 │                                     │
                 │ 模型                                   │
                 │ ┌─────────────────────────────────┐ │
                 │ │ gpt-5.6-sol              已启用  │ │
                 │ │ gpt-5.6-luna             已停用  │ │
                 │ └─────────────────────────────────┘ │
                 │                                     │
                 │ [测试连接]             [取消] [保存] │
                 └─────────────────────────────────────┘
```

- 新增和编辑共用同一个表单；标题由模式决定。
- Provider 基础字段和模型列表放在同一个上下文内，但模型新增可以打开二级小弹窗，避免主表单过长。
- `测试连接`是独立动作，显示进行中、成功和失败状态；不能伪装成保存结果。
- 保存前保留用户当前输入；校验失败时将焦点移到首个错误字段，并在表单顶部显示错误摘要。

### 3.3 档案页

档案是多个 Codex 配置文件的切换入口，不与 Provider 列表混在首页。

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 档案                                                        [+ 新建档案]       │
│ 管理不同工作环境使用的 Codex 配置文件。                                      │
│                                                                              │
│  工作                                                当前使用                 │
│  profiles/work.config.toml                            [选择] [编辑] ⋯        │
│                                                                              │
│  个人                                                                        │
│  默认 Codex config.toml                                [选择] [编辑] ⋯        │
└──────────────────────────────────────────────────────────────────────────────┘
```

- 当前档案只允许一个，激活路由时必须明确使用哪个档案。
- 删除档案前检查是否被 Route 引用；被引用时给出迁移动作，而不是只显示错误字符串。
- `恢复备份`放入更多菜单，避免与高频的选择和编辑竞争视觉权重。

### 3.4 设置页

设置页采用分组列表，不采用一张长表单。

| 分组 | 设置项 |
| --- | --- |
| 应用 | 开机自动启动、关闭窗口时最小化到托盘 |
| Codex | Codex 可执行文件路径、默认 Profile |
| 数据 | 配置存储位置、备份恢复 |
| 关于 | 版本、运行环境、诊断信息 |

每项设置使用“标题 + 当前值 + 右侧控件”的行式布局；需要路径选择的设置打开系统文件选择器，不让用户手填复杂路径。

## 4. 交互状态原型

### 激活 Route

```text
点击「切换」
  → 行内显示「正在备份…」
  → 显示「正在写入 Codex 配置…」
  → 显示「已切换到 CPA / gpt-5.6-sol」
  → 如果勾选重启，再显示「正在启动 Codex…」
```

流程期间保持列表可见，禁用会产生冲突的操作。失败时显示具体阶段和恢复结果，例如：`写入失败，已恢复上一次配置`。

### 必须设计的状态

| 状态 | 视觉与行为 |
| --- | --- |
| 首次空态 | 解释下一步，提供唯一主按钮 `添加 Provider` |
| 首次加载 | 保留壳层与标题，只在列表区域显示 2–3 行骨架 |
| 刷新中 | 顶部刷新按钮变为进行中，列表不闪烁清空 |
| 激活中 | 当前行显示阶段状态，禁用重复激活 |
| 成功 | 状态点变绿，摘要更新，短提示自动消失 |
| 失败 | 顶部 `role=alert` 错误条 + 行内字段错误；保留输入 |
| Codex 未运行 | 状态点为灰色，提供 `启动 Codex` |
| Provider 无模型 | 行内提示 `添加模型后才能激活`，提供 `添加模型` |

## 5. 视觉令牌

这套令牌用于“低发光、深色、开发者工具”的桌面场景。亮色主题可后续基于同一语义令牌扩展，但 V1 默认深色。

### 颜色

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `surface-0` | `#0E1519` | 窗口背景 |
| `surface-1` | `#141E23` | 导航和工具栏 |
| `surface-2` | `#1A272B` | 列表行、弹窗 |
| `surface-selected` | `#203832` | 当前项背景 |
| `border-subtle` | `#26363A` | 分隔线 |
| `border-strong` | `#3A5153` | 输入框和悬停边界 |
| `text-primary` | `#E7F0EE` | 标题和主要内容 |
| `text-secondary` | `#A4B6B5` | 辅助说明 |
| `text-muted` | `#6D8181` | 次要元信息 |
| `accent` | `#62E6C2` | 激活、主要按钮、焦点 |
| `accent-strong` | `#2EBB96` | 激活按钮悬停 |
| `warning` | `#F0B45C` | 警告和需要重启 |
| `danger` | `#E77B80` | 错误和删除 |

### 字体与尺寸

- UI 字体：`IBM Plex Sans`，本地打包，回退到 `Segoe UI`。
- ID、URL、模型 ID：`JetBrains Mono`，仅用于数据，不用于所有标签。
- 正文 13 px；辅助文字 11 px；页面标题 20 px；弹窗标题 16 px。
- 4/8 px 间距节奏；常用间距为 8、12、16、24、32 px。
- 圆角：输入和按钮 6 px；列表容器 10 px；弹窗 12 px；不使用胶囊式大圆角作为主要结构。
- 动效：150 ms 悬停和按下反馈；200 ms 弹窗；减少动效时完全跳过位移和渐变。

## 6. 原型验收标准

- 用户在启动后 3 秒内能看到当前 Provider、Model、Profile 和 Codex 状态。
- 用户不滚动页面即可完成一次 Provider 切换。
- Provider 的添加、编辑、连接测试都在独立上下文中完成，首页不会被表单撑长。
- 档案、设置与 Provider 有明确的页面边界。
- 所有图标来自同一套 SVG 图标库，不使用 emoji 充当系统图标。
- 键盘可以完成导航、打开弹窗、提交和关闭；焦点始终可见。
- 错误同时有文字说明和语义状态，不只依赖红色。
- 空态、加载、激活中、失败、成功和 Codex 未运行都有明确设计。
